# 0.2.5 — Hermes 安装与 Windows 生命周期修复

- 安装前 `--check` 验证实际 Hermes Python、源码能力和 Node.js 22+；安装阶段不要求原生 A2A 已启动，运行阶段继续严格验证服务/认证。
- 安装器保存已验证的运行时路径和非敏感 Connector 参数，支持 `--upgrade` 停止受管理的旧 runner、原子备份插件并保留凭据。旧版/孤立进程和遗留锁必须核实后处理。
- Windows 使用当前用户/SYSTEM 的受保护 DACL，不依赖 `os.fchmod`；存活检查不再使用 Python `os.kill(pid, 0)`。
- 通过实例 ID 和 IPC 管理停止，清理自己的子进程、兼容服务和锁；手动启动的新版 runner 也能由工具统一检查和停止。
- 配对先启动受管理的 worker，再显示有效审批；同一个 worker 负责请求续期和批准后的兑换，不要求审批期间重启 Gateway。
- 新增 `a2a_connector_status`、`/a2a_connector status|doctor` 和外部 Python 管理入口；区分进程存活、凭据保存和实时隧道健康，输出不含 token。
- stdout/stderr 一起写入私有日志。非敏感专用配置每次操作重读，修改后只需重新启动 Connector；宿主注册/platform/.env 修改从外部统一加载一次。
- 增加原生 Windows/Python 3.11 CI，以及过期审批更新、单次兑换、重复启动、手动 runner 复用和正常停止的完整流程测试。

Windows 0.2.4 旧进程清理、升级和完整验收顺序见 [Hermes 安装指南](../install/hermes.md)。升级不会自动重启正在承载安装聊天的 Gateway。
